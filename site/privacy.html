Privacy & submissions

Updated October 16, 2026

Browsing

GitHub Pages hosts the community site. A separate report service and database run in the project owner's Cloudflare account. Your browser requests the reviewed registry from these services. Their infrastructure can receive ordinary connection information such as IP addresses and browser headers. This site adds no analytics or advertising.

Your theme preference stays in your browser's local storage. Build details, imported files, and submission receipts stay in browser memory unless you explicitly save a file. They are not automatically uploaded or saved between visits.

Shared compatibility links can include your search, filters, sort, and page in the URL fragment. Report links include a public report identifier. These links do not include a draft report or private receipt unless you explicitly copy a submission status link.

Submitting without an account

No account is required to submit a report. The form sends only the displayed report, publication consent, a hidden spam-trap field, and short-lived browser-verification data. No email, name, console address, or pairing code is requested.

Reports can include game and base identifiers, region/revision, UIF version, environment, outcome, test checks, notes, allowlisted settings, and SHA-256 runtime/source fingerprints. These are useful for comparing builds. They do not establish file authenticity or independent hardware verification. Manual entries explicitly lack captured build evidence.

Do not submit games, keys, saves, runtime binaries, support bundles, local file paths, or personal information in free text. Review everything before consenting. Server validation rejects unknown fields and oversized reports but cannot reliably detect every personal detail in names or notes.

Saving a report downloads a local JSON file without submitting it. During submission, the form is locked to the report being sent. Stop waiting cancels your browser's request, but the service may already have received it. Retrying identical contents returns the same receipt.

Review, publication, and retention

New reports are stored in a private moderation queue. Only the configured reviewer account can approve publication. The reviewer uses GitHub sign-in; submitters do not. Approved reports become publicly readable and downloadable. A review checks scope and privacy and is not a claim that the reviewer reproduced the result.

Reviewer sign-in requests public GitHub identity only, not repository access or write permission. GitHub access tokens are used transiently for identity verification and are not stored. The service keeps a hash of an opaque reviewer session token, GitHub account ID and login, and a two-hour expiry. Its session cookie is Secure and HttpOnly. Browser-bound login state expires after ten minutes and is single-use. Expired session/state records are pruned on later login activity; logout deletes the current reviewer session.

Keep your private receipt to check review status or request a correction/removal through the UIF project page. Saving a receipt is an explicit local download. A copied community status link carries the receipt in its URL fragment, which is not sent in the initial page request. When you open that link or check a receipt, the site sends the receipt to the report service to retrieve its review state. Status lookup shows no pending report contents and requires no account. Anyone with the receipt can check that status; keep it private.

Rejection or removal erases the submitted contents from the active database. Pending/rejected records older than 90 days are pruned when the service next processes a submission or review. Approved reports remain until removed. Hosting providers may retain logs or backups under their own policies; public copies cannot be recalled.

Abuse prevention

Submissions use signed, expiring browser verification, one-use challenges, duplicate detection, size/schema limits, and server-side intake limits. Where the host supplies a network address, the service uses a keyed hash for short-lived rate limiting rather than storing the raw address in its database. Rate records expire and are pruned on later submission/review activity. The infrastructure itself may still log connection information.

Optional GitHub submissions

The GitHub issue form remains available as an alternative. GitHub requires an account, and the issue, attached report, and your GitHub identity are public immediately under GitHub's policies. GitHub submissions are not automatically added to the reviewed registry.
