# Cloudflare Report Service

The public website stays on GitHub Pages. This Worker hosts anonymous report
intake, private review, and GitHub reviewer sign-in in the owner's Cloudflare
account. It reuses the framework-independent handler in `service/` with an
explicit authorization context; visitor-supplied identity headers never authorize
the Worker. GitHub sign-in requests public identity only, not repository access.

## Deployment Configuration

Provision a dedicated D1 database and apply `service/drizzle/0000_hard_havok.sql`
and `worker/auth-schema.sql`. Do not apply these to an unrelated database.
Register a dedicated GitHub OAuth app with the deployed Worker's exact HTTPS
origin followed by `/auth/callback` as its callback URL. The immutable reviewer
account ID is configured in `tools/prepare-cloudflare.mjs`.

`node tools/prepare-worker.mjs` prepares only the explicitly listed public assets.
`node tools/prepare-cloudflare.mjs --database-id YOUR_DATABASE_ID --origin YOUR_HTTPS_ORIGIN --github-client-id YOUR_CLIENT_ID`
prepares an ignored Wrangler configuration at `outputs/cloudflare/wrangler.json`.
Set `CLOUDFLARE_ACCOUNT_ID` in the deployment process, not in browser source.
Deploy with Wrangler using this configuration. The service stays closed until its
required runtime configuration is present.

## Two Different Secrets

Create both entries under the Worker's **Settings > Variables and Secrets > Add**,
choosing type **Secret**. Names are case-sensitive:

| Name | Value | Purpose |
| --- | --- | --- |
| `INTAKE_SECRET` | Independently generated cryptographically random signing key, at least 32 characters | Browser verification, CSRF proofs, and hashed rate-limit identifiers |
| `github_client_secret` | Client secret generated by the dedicated GitHub OAuth app | Server-to-server GitHub token exchange only |

Do not put the GitHub client secret into `INTAKE_SECRET`, reuse one value for both
purposes, or put either value in source, chat, command-line arguments, or logs.
The public Client ID is a separate runtime variable named `GITHUB_CLIENT_ID`.
If editing an existing secret, its name is fixed: use **Add** to create the other
entry rather than overwriting the first value.

Replacing `INTAKE_SECRET` invalidates old browser challenges and CSRF proofs.
Coordinate it with active reviewers; stored reports and receipt IDs are not
encrypted or derived with this key and are not replaced by key rotation.
Only inspect secret names, never export their values for troubleshooting.

## Verification

Run `node --test tests/*.test.mjs service/tests/*.test.mjs worker/tests/*.test.mjs`.
`/health` confirms configuration presence, not that GitHub accepted a credential.
Test the real owner sign-in, reject/erase a clearly marked authored test report,
then verify its status-only receipt and exclusion from the public registry before
switching the public website to the Worker. Never publish a deployment fixture
as a compatibility result or silently abandon reports on a previous service.

GitHub requests use `redirect: 'manual'` and reject every non-2xx response.
Workers does not implement `redirect: 'error'`. Tokens are only sent to the fixed
GitHub endpoints; no redirect is followed. Unexpected OAuth diagnostics expose
only fixed operation/category labels, never exception messages or token contents.
Do not refresh a failed callback: start again at `/review` for new one-use state.
